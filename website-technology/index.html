01 · About me

I learn technology by building real projects.

My journey is driven by curiosity, experimentation and the desire to understand how the pieces of a digital product fit together.

I'm Yusuf Rokib, known as Don Martial, a self-driven technology learner, software developer, digital product builder and graphic designer. I enjoy learning by taking an idea, working out how it might function, and building a version I can test, improve and learn from.

Rather than limiting myself to one area of technology, I explore different parts of the software development ecosystem. That includes frontend development, backend systems, databases, APIs, cloud platforms, authentication, payment integrations and digital product design. I am interested in how the pieces work together, not only in how to write one part of the code.

Many of my projects begin with one simple question: “What if I build this myself?” From there, I research the technology, plan the system, design the interface, write and test code, work through errors, deploy where appropriate, and keep improving what I learn.

I see every project as an opportunity to understand a new tool, solve a problem, or improve the way I approach technology. Some projects become useful products; others are experiments, prototypes or learning exercises. Each can teach me something valuable.

“Build it. Break it. Understand it. Fix it. Improve it.”

A little about my mindset

I don't believe you need to know everything before you start building. Sometimes understanding comes from trying, making mistakes, asking questions and working through a problem.

I'm interested in:

  • Learning through hands-on projects
  • Understanding the why behind the code
  • Connecting frontend, backend and data
  • Building useful, thoughtful user experiences
  • Improving a product one step at a time

09 · My learning philosophy

I want to understand why systems work.

I'm not interested in only memorising syntax. I want to learn how and why different technologies work together.

When I encounter a technology I don't understand, I try to break it into smaller questions. What is it? Why does it exist? How does it work? How does it communicate with other systems? How can I use it? Can I build something with it—and can I improve what I build?

Sometimes a bug is where the real lesson begins. A failed deployment, an unexpected API response or a database problem can reveal what I still need to learn. I try to use those moments to investigate, repair the issue and understand the cause.

I don't expect every first version to be perfect. My focus is to build, test, learn and keep improving one project at a time.

The learning loop

  • Ask a question
  • Research and break it down
  • Build a small example
  • Test what happens
  • Debug and understand
  • Apply the lesson
  • Improve the result
