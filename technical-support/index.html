03 · How a request works

Give the issue a clear starting point.

You do not have to know the technical cause. Clear symptoms and context make a request easier to understand.

01

Describe the project

Share the site, app, repository or service name and a public link if available.

02

Explain what happened

03

Share safe evidence

Add error text or a screenshot after hiding personal details, tokens and private data.

04

Discuss next steps

Clarify the issue, scope, access needs and any cost before work is agreed.

04 · Before contacting me

Help me understand the issue faster.

Include what you can safely share, but protect your accounts, your customers and your private systems.

Helpful details to include

  • Website, application or project name and public URL.
  • A short description of the issue or feature you want.
  • The expected result versus what happens now.
  • Device, browser or environment where it appears.
  • Error messages, approximate time and relevant steps.

Keep your account and data safe

  • Do not send passwords, one-time codes or recovery codes.
  • Never include API keys, private keys, access tokens or database credentials.
  • Hide customer data, payment details and private messages in screenshots.
  • Share access only through a secure, agreed method if necessary.
  • Confirm ownership and permission before requesting site access.
Important: This page does not promise 24-hour support, guaranteed response times or free fixes. Scope, availability, access requirements and any applicable cost should be agreed before work begins.

07 · Frequently asked questions

Before you send a support request.

These notes help set clear expectations and protect your project information.

Will my form be submitted automatically?

No. The form prepares a WhatsApp message draft for review. You need to review it and tap Send yourself; this site does not save the form in a database.

Can I ask for a new website or feature?

Yes. Choose “New feature or development” and describe the goal, required functions, intended users and relevant timeline. Scope and pricing should be agreed before work starts.

Should I send a password to help fix an issue?

No. Never send passwords, one-time codes, private keys, access tokens or production database credentials in a support message. Use a secure, agreed access method only when necessary.

How quickly will I get a response?

No response-time or around-the-clock support guarantee is made on this page. Explain any time-sensitive context in your enquiry and confirm availability directly.

What if I don't know what is broken?

That's okay. Describe what you clicked, what you expected, what happened and any error message. You do not need to know the technical cause.

Is this the same as Agrolyst customer support?

This page is for technical and developer enquiries. For Agrolyst products, farm services, orders or business partnerships, use the company's main contact options.
